## 開始使用

1. 照平常一樣開 Claude Code（CLI 或 Desktop 的 Code 分頁都可以）。每個 session 開始時，plugin 會自動拉起 collector，不必自己啟動任何東西。
2. 瀏覽器打開 <http://127.0.0.1:4801>。
3. 右上角顯示「已連線」就開始收資料。之後開的每個 session 都會自動出現在畫面上。

幾件要知道的事：

- **追蹤不花 token**，也不會攔截或改變 Claude Code 的行為。危險指令只會標示，不會擋下。
- 所有 session 都結束、再閒置 10 分鐘後，collector 會自己退出；下一個 session 開始時再自動拉起。網頁會顯示「已斷線，重新連線中…」，collector 回來就自動接上。
- 紀錄保留 30 天。

## 畫面總覽

```text
┌ 標題列：專案選單、連線狀態、統計數字（進行中、待確認、改動、費用…）──────────────┐
├ 左欄 ──────────────┬ 中間 ──────────────────────────────────────────────────┤
│ 專案檔案 │ Sessions │ 分頁：全部串流｜各 session｜+N｜⟲ 專案回放                    │
│                    │ ┌ 合流串流 ─────────────┬ 改動紀錄 ───┬ 修改情形 ─────┐ │
│ 檔案樹             │ │                       │ Agents      │（diff）       │ │
│                    │ ├ 需要注意 ─────────────┤             │               │ │
│                    │ └───────────────────────┴─────────────┴───────────────┘ │
└────────────────────┴────────────────────────────────────────────────────────┘
```

- **標題列**：最左邊是專案選單（只有一個專案時不顯示），接著是連線狀態，右邊是今天的統計數字。
- **左欄**：「專案檔案」是檔案樹；「Sessions」是所有 session 的清單（含已結束的）。
- **中間上方的分頁**：「全部串流」是所有 session 合在一起的主畫面；每個進行中的 session 一個分頁；放不下的收進「+N」；最右邊是「⟲ 專案回放」。

連線狀態的意思：

| 顯示 | 意思 |
| --- | --- |
| 已連線 | 正常 |
| 連線中…／已斷線，重新連線中… | collector 沒在跑或重啟中，會自動重連 |
| collector 版本不相容，請重新整理或更新 | 網頁和 collector 版本不同，重新整理頁面；還是不行就重新放好 `web/`（見安裝手冊「更新」） |

## 合流串流

所有 session 的思考、訊息、讀寫檔案、指令與輸出、git 操作、subagent 的動作，依實際發生的順序排成一條。每行開頭標示：

```text
[專案] [session id 前 8 碼] [agent] 內容
```

- `[專案]` 只在「全部專案」而且有多個專案時出現；`[agent]` 是 `main` 或 subagent 的名稱。
- 每個 session 一個固定顏色，串流、分頁、注意佇列都用同一個顏色。

**篩選**：

- **session：** 點某個 session 標籤只看它，再點一次取消。
- **類型：** 思考、訊息、讀、改、寫／派工、指令與輸出、狀態，可以只留想看的類型。

**展開**：內容太長或有輸出的行（指令輸出、長訊息、思考全文）可以點一下展開，再點一次收起。

**行尾的標記**：

| 標記 | 意思 |
| --- | --- |
| `…` | 還在執行 |
| `✓ 1.2s` | 完成，花了多久 |
| `✗ exit 1` | 失敗與原因 |
| `中斷` | 使用者按 Esc 中斷 |
| `⚠ …` | 命中危險規則（只標示，不攔截） |
| `延遲` | 這筆比較晚才收到，排在它實際發生的位置 |
| `無 transcript` | 讀不到這個 session 的 transcript，只能顯示工具事件（看不到思考與訊息） |

**串流下方的「即時：N 個動作進行中」**：Claude Code 已經開始執行、但 transcript 還沒寫到的動作。點一下開成浮動視窗，可以拖動與縮放。

串流最多保留最近 3000 行；更早的在 session 分頁裡用「↑ 載入更多」看。

## 需要注意（注意佇列）與通知

串流下方的「需要注意」列出要你處理的 session，依種類排序，同種類新的在上：

| 種類 | 什麼時候出現 | 什麼時候自己消失 |
| --- | --- | --- |
| **危險** | 執行了命中危險規則的指令（例如 `rm -rf`、`git push --force`、`git reset --hard`） | 不會自己消失，要按「已確認」 |
| **失敗** | 同一個 agent 的指令連續失敗兩次 | 之後有指令成功 |
| **等你** | Claude 在問你問題或等你同意權限。「等你回答（推測）」是 Claude 最後寫了一段話、之後 30 秒都沒有動作時的推測 | 你回答、或有新的動作 |
| **完成** | 一輪做完，等你看結果 | 你送出下一個 prompt |

每一列可以：

- **點整列或「查看」**：切到那個 session 的分頁。
- **「已確認」**：從佇列移除。所有開著的視窗、別台電腦都會同步消失。
- **「全部確認」**：一次確認目前看得到的所有列。

危險列變淡、寫「已結束」，表示那個指令已經執行完，但還沒有人確認。用 `view` 金鑰從遠端登入時不能按「已確認」；專案回放中也不能。

**通知**（「需要注意」標題旁的三個開關，預設全關，每個瀏覽器各自記住）：

- **頁內提示**：畫面右上角跳出提示。
- **瀏覽器通知**：第一次打開時瀏覽器會問要不要允許。被封鎖的話，開關旁會說明，要到瀏覽器的網站設定裡改。
- **提示音**：瀏覽器規定要先在頁面上點過或按過鍵才能出聲；開關旁出現提示時點一下頁面即可。

同時開了好幾個主視窗時，聲音和瀏覽器通知只由其中一個發，不會重複；監視器視窗不發通知。

## 單一 session 分頁與監視器視窗

點上方的 session 分頁（或注意佇列的「查看」）會看到這個 session 的完整內容：

- **標題列**：session id、第一個 prompt、模型、分支、目錄、commit 數與最後一個 commit、危險指令數、費用。
- **目前狀態**：正在做什麼、是哪個 agent。
- **思考**：最近一段思考。
- **⚠ 危險指令**：這個 session 執行過的危險指令清單。
- **終端機**：這個 session 的完整串流。捲到最上面按「↑ 載入更多」可以一路看到開頭。
- **正在修改的檔案**：這個 session 碰過的檔案，點檔案看 diff。
- **開出來的 agent**：每個 subagent 一條，看得到它在做什麼、做完沒有。

**監視器視窗**：分頁上的 **⧉**（或 session 畫面右上角的「⧉ 監視器」）會把這個 session 開成獨立的小視窗，可以拖到第二個螢幕。它自己連 collector，關掉主視窗也能繼續看。

session 太多、分頁放不下時，收進「+N」，點一下列出來。

## 專案檔案（檔案樹）與分支視窗

左欄「專案檔案」顯示專案的檔案（依 `.gitignore` 過濾），並標出 session 對每個檔案做了什麼：

| 標示 | 意思 |
| --- | --- |
| 青色方塊 | 讀過的次數 |
| 橘色方塊 | 改過的次數 |
| 紫色方塊 | 新建 |
| 紅色方塊 | 失敗（改檔或寫檔失敗） |
| ● | 現在正有 session 在碰這個檔 |
| 檔名變色 | 依上方選的基準，這個檔有未合併的改動或是新檔 |
| ⚠ | 衝突候選：兩個以上的分支或 worktree 都改了這個檔，而且內容不同 |

上方的下拉選單決定「檔名變色」的基準：

| 基準 | 用途 |
| --- | --- |
| 相對整合分支 | 和 `develop`／`main`／`master` 相比，所有 worktree 有哪些改動還沒合併（預設） |
| 本次開啟以來 | 這個頁面開著以來被改過的檔 |
| 單一 session | 只看某一個 session 改過的檔 |
| 相對某個 commit | 填 commit hash，看那之後改了什麼 |

**⎇ 分支**：開出分支視窗。上半是像 VS Code Git Graph 的 commit 圖與分支標籤，下面每個 worktree 一列：有哪些 session 在上面、領先／落後整合分支幾個 commit、還沒 commit 的檔、和其他分支同時改到的檔。點 commit 或檔案看 diff。

## 改動紀錄與修改情形

- **改動紀錄**：所有 session 的 Edit／Write，最新的在上面，「全部專案」時依專案分組。
- **修改情形**：點左邊任一筆，右邊顯示帶行號的 diff。新檔顯示內容（太長時只顯示前面）。

## Agents 與上方的統計數字

**Agents**：每個 session 的 main 與 subagent，各自正在做什麼、做完沒有、失敗或被停止。

**上方的統計數字**（今天，依你的時區）：

| 數字 | 意思 |
| --- | --- |
| 進行中 | 還在跑的 session |
| 待確認 | 注意佇列的件數 |
| Sessions／Agents | session 數、subagent 數 |
| 改動／新檔案 | Edit 次數、新建檔案數 |
| 指令／失敗／危險指令 | 執行的指令、失敗的工具呼叫、命中危險規則的指令 |
| Commits | session 裡做的 commit |
| 思考 tokens、費用 | 滑鼠移過去（或用 Tab 鍵選到）看依模型的明細。費用是依內建單價估算的，不是帳單金額；單價可以用 `~/.coding-lab/prices.json` 調整（見 README「設定」） |

## Sessions 清單與回放

左欄切到 **Sessions**：所有 session（進行中與已結束），新的在上面。每一列有狀態（執行中、閒置、完成、失敗、注意）、分支、commit 數、危險指令數。

**回放一個已結束的 session**：那一列右邊按 **▶ 回放**，會開成分頁，從存下來的紀錄讀回完整串流、碰過的檔案與改動；捲到最上面按「↑ 載入更多」看到開頭。

**回放整個專案**（同一段時間裡所有 session 一起做了什麼）：

1. 按上方分頁最右邊的 **⟲ 專案回放**。整個主頁切進回放模式，預設載入目前的專案、最近 3 小時。
2. 選專案與時間範圍（最近 3 小時、今天、昨天，或自訂後按「載入」）。
3. 按 **▶** 播放、**⏸** 暫停，旁邊選速度（1×、10×、60×、600×）；拖動時間軸跳到任一時刻。
4. 串流、注意佇列、改動紀錄、Agents、統計數字都會變成那個時刻的樣子。檔案樹的檔案清單仍是現在的 git 狀態，只有讀、改、新建的標記跟著時間軸。
5. 回放中不能按「已確認」，也不會跳通知。切回「全部串流」或任一個 session 分頁就回到即時畫面。

## 多個專案

collector 收這台機器上所有 Claude Code 的事件。有兩個以上專案時，標題列出現專案選單：

- **全部專案**（預設）：串流每行多一個專案標籤，檔案樹每個專案一段（點標題列可收起），改動紀錄依專案分組，標題列的 ⎇ 開那個專案的分支視窗。
- **單一專案**：只看這個專案。其他專案只是隱藏，注意佇列會提示「其他專案還有 N 件」。選擇會記在瀏覽器裡。

session 的目錄在另一個 session 的目錄底下（worktree、子目錄）就算同一個專案；專案名是目錄的最後一段。

## 從別台電腦或手機看

**SSH 通道**（最簡單、不用改設定）：在你的電腦執行

```bash
ssh -N -L 4801:127.0.0.1:4801 <跑 Claude Code 的那台>
```

再打開 <http://127.0.0.1:4801>。VS Code Remote 可以在「連接埠」面板轉送 4801。

**Tailscale／ZeroTier 直連**（手機也能看）：在那台設定 `[web].bind` 並建金鑰，步驟見[安裝手冊「確認有在追蹤」](install.md#確認有在追蹤)。第一次打開會出現登入頁，貼上 `coding-lab key create` 印出的 `clk_…`，之後 30 天不必再貼。手機不好打字時，在那台執行 `coding-lab key login-link`，打開它印出的網址（5 分鐘內、只能用一次）。

遠端看時有幾個差別：

- 讀 `.env`、金鑰檔等敏感檔案的工具輸出不會顯示（要在本機看）。
- 思考預設只顯示長度，點開那一行才載入全文（`remote_thinking` 可改成 `hide` 或 `show`）。
- `view` 金鑰只能看；`operate` 金鑰才能按「已確認」。
- 登入狀態是 30 天的 cookie。要讓某台裝置失效，在那台 collector 上撤銷它用的金鑰（`coding-lab key revoke <id>`，`key list` 看 id），立即生效。

## 一次看多台（hub）

好幾台各自跑 Claude Code 時，可以在自己的電腦用 `coding-lab hub` 合成一頁：打開它在終端機印出的網址（`http://127.0.0.1:4802/?token=…`，每次啟動都不同；第一次打開後換成 cookie，網址列不再帶 token）。畫面和單機一樣，每行多一個 `[主機]`；某台斷線時它的 session 標「離線」，連回來自動補齊。hub 重新啟動後要用新印出的網址。設定方式見[安裝手冊「一次看多台伺服器（hub）」](install.md#一次看多台伺服器hub)。

## 指令速查

執行檔在 `~/.coding-lab/bin/coding-lab`（Windows 是 `coding-lab.exe`）。

| 指令 | 用途 |
| --- | --- |
| `coding-lab healthz` | collector 有沒有在跑、版本、session 數 |
| `coding-lab stop` | 請 collector 正常結束（更新執行檔前用） |
| `coding-lab serve` | 前景執行 collector（看錯誤訊息用；平常不需要） |
| `coding-lab config` | 印出實際生效的設定 |
| `coding-lab prune` | 立刻清掉 30 天前的紀錄（collector 沒在跑時才會動） |
| `coding-lab key create --name <名稱> [--scope view\|operate] [--expires 90d]` | 建遠端查看用的金鑰（只印一次） |
| `coding-lab key list`／`key revoke <id>`／`key login-link` | 列出、撤銷金鑰；印一次性登入網址 |
| `coding-lab service install`／`status`／`uninstall` | 裝成登入（開機）就啟動的常駐服務 |
| `coding-lab hub add <名稱> <網址>`／`coding-lab hub` | 多機總覽（`hub` 印出帶 token 的網址） |

設定檔（`~/.coding-lab/config.toml`）、危險規則（`rules.json`）、單價表（`prices.json`）的格式見 [README「設定」](../README.md#設定)。

## 常見問題

**網頁打不開或一直顯示「重新連線中」**
collector 沒在跑。開一個新的 Claude Code session 就會拉起；或在終端機跑 `coding-lab healthz` 確認。更多情況見[安裝手冊「疑難排解」](install.md#疑難排解)。

**剛開的 session 沒出現**
在裝 plugin 之前就開著的 CLI session 不會被追蹤，關掉重開一個。

**看不到思考與訊息，只有工具事件（標「無 transcript」）**
collector 讀不懂或讀不到這個 session 的 transcript，會自動降級成只顯示工具事件；transcript 恢復後會自動補上。

**頁面頂部出現「⚠ 資料沒有寫進磁碟」**
collector 寫不進資料目錄（磁碟滿、檔案被別的程式鎖住）。畫面照常更新，但這段時間的事件還沒存下來；collector 會每隔一段時間重試，寫進去之後提示自己消失、事件補上。滑鼠移到提示上看錯誤原因，`~/.coding-lab/collector.log` 也有紀錄。

**費用跟帳單不一樣**
費用是依 token 數與內建單價估算的，用來比較 session 之間的花費，不是帳單金額。

**Claude Code 出現 `hook error` 或 `ECONNREFUSED`**
collector 沒在跑時會出現，不影響 Claude Code 運作；開一個新 session 會重新拉起 collector。

**想暫停追蹤**
`claude plugin disable coding-lab`，恢復用 `claude plugin enable coding-lab`。
